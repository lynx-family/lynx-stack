# @lynx-js/testing-environment

[npm](https://www.npmjs.com/package/@lynx-js/testing-environment) · [Source](https://github.com/lynx-family/lynx-stack/tree/main/packages/testing-library/testing-environment) · [Changelog](https://github.com/lynx-family/lynx-stack/blob/main/packages/testing-library/testing-environment/CHANGELOG.md)

`@lynx-js/testing-environment` 是 [Lynx Spec](https://lynxjs.org/api/engine/element-api) 的纯 JavaScript 实现，主要覆盖 [Element PAPI](https://lynxjs.org/api/engine/element-api) 和[双线程模型](https://lynxjs.org/guide/spec#dual-threaded-model)，供 Node.js 使用。总体目标是模拟出足以用于测试的 Lynx 环境子集。

Element PAPI 的实现基于 jsdom，例如 `__CreateElement` 返回的 `LynxElement` 继承自 jsdom 的 `HTMLElement`。因此你可以复用常见的 DOM 测试工具，比如 [`@testing-library/dom`](https://github.com/testing-library/dom-testing-library)（DOM 查询）和 [`@testing-library/jest-dom`](https://github.com/testing-library/jest-dom)（DOM 相关的自定义 jest matcher）等。

## Usage

```js
import { LynxTestingEnv } from '@lynx-js/testing-environment';
import { JSDOM } from 'jsdom';

const lynxTestingEnv = new LynxTestingEnv({ window: new JSDOM().window });
```

使用 `@lynx-js/testing-environment` 时，主要用到包里具名导出的 `LynxTestingEnv` 构造函数。它返回一个 `LynxTestingEnv` 实例，实例上有若干有用的方法和属性，其中 `switchToMainThread` 和 `switchToBackgroundThread` 可以在主线程和后台线程之间切换。

使用后台线程 API：

```js
lynxTestingEnv.switchToBackgroundThread();
// use the background thread global object
globalThis.lynxCoreInject.tt.OnLifecycleEvent(...args);
// or directly use `lynxCoreInject` since it's already injected to `globalThis`
// lynxCoreInject.tt.OnLifecycleEvent(...args);
```

使用主线程 API：

```js
lynxTestingEnv.switchToMainThread();
// use the main thread Element PAPI
const page = __CreatePage('0', 0);
const view = __CreateView(0);
__AppendElement(page, view);
```

注意，不切换线程也仍然可以访问另一个线程的全局变量：

```js
lynxTestingEnv.switchToMainThread();
// use the `backgroundThread` global object even though we're on the main thread
lynxTestingEnv.backgroundThread.tt.OnLifecycleEvent(...args);
```

### Use in Vitest

推荐把它配置为 Vitest 的[测试环境](https://vitest.dev/guide/environment)，例如：

```js
// vitest.config.js
import { defineConfig } from 'vitest/config';

export default defineConfig({
  test: {
    environment: require.resolve(
      '@lynx-js/testing-environment/env/vitest',
    ),
  },
});
```

配置完成后，就可以在测试中直接通过全局变量访问 `lynxTestingEnv` 对象。

如果你是在 ReactLynx 中用 `@lynx-js/testing-environment` 做单元测试，通常不需要手动指定这项配置。

参见 [ReactLynx Testing Library](https://lynxjs.org/react/reactlynx-testing-library.html)，从 `@lynx-js/react/testing-library` 继承相关配置。

### Use in Rstest

如果你的测试运行器已经通过 jsdom 提供了全局 `window`，可以这样加载共享的 Lynx 测试环境：

```js
import '@lynx-js/testing-environment/env/rstest';
```
