# 接口: Artifact

构建产生的、携带至少一个调试
数据源的一个产物。

其标识是 `(filename, tasmSection)`：
  - `filename` 是 asset 的基本文件名（例如 `main-thread.js`、
    `background.fd311de1.js`、`main.css`）。
  - `tasmSection` 是该 artifact 在 `tasm.json` 中的位置，
    用于区分文件名模式相同但位于不同 section 的 artifact。

`tasmSection` 是由嵌套对象各段组成的路径数组，因为原始
key（尤其是 `customSections` 下的 key）本身可能包含点号，
无法安全地折叠为用点号分隔的字符串。示例：

  - `['lepusCode', 'root']`        main-thread.js
  - `['lepusCode', 'chunks', '0']` 异步 main-thread chunk
  - `['manifest', '/<asset-name>']` background JS bundle
  - `['customSections', 'data.v2']` key 中带点号的自定义 section
  - `['css']`                      一个 CSS artifact

## 属性

### debugSources

```ts
debugSources: DebugSource[];
```

该 artifact 的调试源，其顺序与反向符号化的解码链一致。
消费方若从一个运行时位置出发想还原原始源码，
可以从左到右遍历这个列表：

1. `bytecode-debug-info`（如果存在）会将字节码 PC 偏移
   映射回编码后 JS 源码的 `(line, column)`。
2. 然后 `source-map` 再将该 `(line, column)` 映射回
   原始编写的文件。

***

### filename

```ts
filename: string;
```

该 artifact 的寻址名称：即生成文件的 basename，或当 bundle 将其作为自定义 section 携带时的 section 名称。

***

### kind

```ts
kind: "main-thread" | "background" | "css";
```

该资源在 `tasm.json` 中属于哪个 encoder bucket：

- `main-thread` — 运行在 lepusNG 主线程上的 JS（编译到
  `lepusCode` section 中）。
- `background` — 运行在后台 JS 引擎上的 JS（位于
  `manifest` section 中）。
- `css` — 提取出的 CSS chunk（位于 `css` section 中）。

***

### path

```ts
path: string;
```

生成的资源本身相对于 bundler 的路径（例如
`.lynx/main/main-thread.js`）。这与
[SourceMapDebugSource.path](SourceMapDebugSource.mdx#path) 不同，后者指向
与之同级的 `.map` 文件。

***

### tasmSection?

```ts
optional tasmSection?: string[];
```
