Keep nested list cells bound to the correct logical item when an outer list recycles a row for another item, and restore each item's own horizontal scroll position. When the previous item had scrolled its nested list, still has a position restore pending, or the new item has a saved position, the recycled row gets a new native nested list instead of inheriting the previous item's list, and its inner cells are created again; otherwise the native nested list is kept and rebound to the new item. When a nested list is rebuilt from a saved non-zero position, measured cell sizes seed its size estimates to avoid transient height changes. On supported Native runtimes, suppress transitions for one frame when a row that is or contains a nested list is rebound to another item, including the cells of a kept nested list, while retaining normal same-item animations. Cells a nested list recycles while it scrolls keep their usual transitions.

Template reload, first-screen and main-thread hydration keep the existing native nested list and its offset; with `experimental_reEvalJSOnReload`, the re-evaluated entry also keeps tracking those lists and can end a pending transition suppression. Preserve native-held cell roots and first-screen event mappings, forward SSR spread handlers, and keep internal scroll tracking when consumer event handlers are added or removed, when no authored main-thread runtime is present, or when the app bundles its own copy of the same worklet runtime version. A nested list recreated after offscreen edits receives its full data source, and a nested list removed from a recycled row is released. In batch rendering, ready cells finish their rebind after the first flush instead of waiting for deferred siblings, and a deferred cell that finishes after its list was destroyed is dropped. Fix retained move-clone recycle grouping for ordinary lists as well, isolate cloned values, and release cached nested-list callbacks when their owning list is destroyed.

A cell whose `reuse-identifier` equals its `item-key`, inside lists whose containing cells all do the same, is only ever recycled for its own item: its nested lists are not tracked, and a new snapshot of the same key rebinds the cell as before, keeping its native lists, positions and transitions. Scroll tracking otherwise runs on Native runtimes with the UI-method and attribute-read PAPIs; it adds visible-cell data to nested-list scroll events and listens to nested-list scroll and touchstart. Touchstart is observed in the capture phase, unless the engine keeps one main-thread handler per event name and the app has its own main-thread touchstart handler on that list. Transition restoration waits one main-thread animation frame when `lynx.requestAnimationFrame` is available and otherwise restores right after the bind. Web and unsupported runtimes keep their existing binding behavior. A nested list written in the same snapshot as its `<list-item>` (for example `<list-item><list>…</list></list-item>` inline, without a component in between) is always kept and scrolled to the new item's saved position, or the start, with `scrollToPosition`; this change does not claim to repair the engine's anchor behavior for that layout. Transition suppression rewrites a rebound row's string inline style, which also drops per-property inline styles that main-thread code set on it for the previous item. It is not guaranteed for already-parsed `!important` declarations, for a `transition` shorthand set through an object inline style, or for other direct Native style writes outside the SDK style APIs.
