# pluginLynx

The Lynx build engine as an Rsbuild plugin. It builds a Lynx app with the Rsbuild CLI directly, without the Rspeedy CLI.

DSL plugins such as [`pluginReactLynx`](/plugins/plugin-react) register the engine automatically when it is missing, so you only add `pluginLynx` yourself to pass the options below. Rspeedy registers it for you as well and forwards `output.filename` and `performance.profile` from `lynx.config.ts`.

## Usage

Register the plugin next to a DSL plugin in `rsbuild.config.ts`. The environment name (`lynx` below) becomes the `[platform]` placeholder of the bundle filename, so the default output of this config is `dist/main.lynx.bundle`.

```ts title="rsbuild.config.ts"
import { defineConfig } from '@rsbuild/core'
import { pluginReactLynx } from '@lynx-js/react-rsbuild-plugin'
import { pluginLynx } from '@lynx-js/rsbuild-plugin'

export default defineConfig({
  source: {
    entry: { main: './src/index.tsx' },
  },
  environments: {
    lynx: {},
  },
  plugins: [
    pluginLynx({
      performance: { profile: false },
    }),
    pluginReactLynx(),
  ],
})
```

Then use the Rsbuild CLI:

```bash
rsbuild dev
rsbuild build
```

## Migrating from Rspeedy

Replace `rspeedy dev` / `rspeedy build` with `rsbuild dev` / `rsbuild build`, rename `lynx.config.ts` to `rsbuild.config.ts` and import `defineConfig` from `@rsbuild/core`. The two options Rspeedy used to forward to the engine are now passed to `pluginLynx` directly:

| `lynx.config.ts` (Rspeedy) | `pluginLynx()` (Rsbuild) |
| --- | --- |
| `output.filename` as a string | `output.filename.bundle` |
| `output.filename.bundle` | `output.filename.bundle` |
| `output.filename.template` (deprecated) | `output.filename.bundle` |
| `performance.profile` | `performance.profile` |

Everything else in `output`, `source`, `dev` and `server` keeps the Rsbuild shape and stays in `rsbuild.config.ts`. The engine applies Lynx-specific defaults on top of the Rsbuild ones (bundle target, chunk loading, CSS extraction, source maps) and only overrides a setting when another plugin has not already set it.

### `output` \{#output\}

- **Type:** [`LynxOutput`](#output)

The build outputs.

#### `output.filename` \{#output-filename\}

- **Type:** [`LynxFilename`](#output-filename)

The names of the emitted files.

##### `output.filename.bundle` \{#output-filename-bundle\}

- **Type:** [`BundleFilename`](#bundlefilename)
- **Default:** `'[name].[platform].bundle'`

The name of the bundle files.

The following placeholders are supported:

- `[name]`: the name of the entry.
- `[platform]`: the name of the Rsbuild environment.

#### `output.minify` \{#output-minify\}

- **Type:** [`LynxMinify`](#output-minify)

The per-thread minifier options.

| Name | Type | Default | Description |

### `performance` \{#performance\}

- **Type:** [`LynxPerformance`](#performance)

The performance options.

#### `performance.profile` \{#performance-profile\}

- **Type:** `boolean`

Whether to capture timing information in Lynx runtime integrations such as
ReactLynx.

A framework includes runtime information using `console.profile` when this
is enabled.

### `isPluginLynxRegistered()` \{#ispluginlynxregistered\}

```ts
isPluginLynxRegistered(host: { isPluginExists: any }, environments: string[]): boolean
```

Whether the Lynx build engine is already registered.

The engine is a global one. `isPluginExists` without an environment only
reports the global plugins, so it misses an engine a caller — `rslib`, for
one — registered on an environment instead.

### `LynxConfig` <span className="api-badge api-badge-beta">Beta</span> \{#lynxconfig\}

The Lynx config that `pluginLynx` exposes to other plugins.

The data mirrors [`LynxPluginOptions`](#lynxpluginoptions), so a plugin reads
`config.output.filename` the same way it reads `output.filename` from
`api.getRsbuildConfig()`. Values that depend on the entry being built are
derived by the methods, which travel with the data so that the plugin that
built the config is always the one that resolves it.

```js
const lynx = getLynxConfig(api)
const filename = lynx.resolveBundleFilename({
  entryName: 'main',
  platform: environment.name,
})
```

| Members | Type | Description |
| --- | --- | --- |
| <a id="lynxconfig-output"></a>`output` <span className="api-badge api-badge-beta">Beta</span> | [`LynxOutput`](#output) | The build outputs. |
| <a id="lynxconfig-performance"></a>`performance` <span className="api-badge api-badge-beta">Beta</span> | [`LynxPerformance`](#performance) | The performance options. |
| <a id="lynxconfig-resolvebundlefilename"></a>`resolveBundleFilename` | `resolveBundleFilename(context: { entryName: string; platform: string }): string` | Resolve the name of the bundle file of an entry. |
| <a id="lynxconfig-resolveintermediatedir"></a>`resolveIntermediateDir` | `resolveIntermediateDir(context?: { entryName?: string }): string` | Resolve the directory of the intermediate files. |
| <a id="lynxconfig-resolvelazybundlefilename"></a>`resolveLazyBundleFilename` | `resolveLazyBundleFilename(context: { platform: string }): string \| undefined` | Resolve the name of the lazy bundle files. |
