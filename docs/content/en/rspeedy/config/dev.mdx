# dev

Options for the development server and hot module replacement: what the dev client connects to, how updates are delivered to the device and whether the bundle is written to disk while developing.

## At a glance

{/* @api ConfigOverview package="rspeedy" type="Config" path="dev" */}

| Name | Type | Description |
| --- | --- | --- |
| [`assetPrefix`](#dev-assetprefix) | `string \| boolean` | The [`Dev.assetPrefix`](#dev-assetprefix) is used to set the URL prefix for static assets during development. |
| [`hmr`](#dev-hmr) | `boolean` | Whether to enable Hot Module Replacement (HMR). |
| [`liveReload`](#dev-livereload) | `boolean` | Whether to enable live reload functionality. |
| [`progressBar`](#dev-progressbar) | `boolean \| { id?: string }` | Whether to display progress bar during compilation. |
| [`watchFiles`](#dev-watchfiles) | `WatchFiles \| WatchFiles[]` | Watch specified files and directories for changes. When a file change is detected, it can trigger a page reload or restart the dev server. |
| [`writeToDisk`](#dev-writetodisk) | `boolean \| ((filename: string) => boolean)` | Used to control whether the build artifacts of the development environment are written to the disk. |

{/* @api-end */}

## Options

{/* @api ConfigOptions package="rspeedy" type="Config" path="dev" */}

### `dev.assetPrefix` \{#dev-assetprefix\}

- **Type:** `string | boolean`
- **Default:** `undefined`

The [`Dev.assetPrefix`](#dev-assetprefix) is used to set the URL prefix for static assets during development.

During `rspeedy dev`, if this option is not set to `false`, the dev plugin normalizes it to `http://<detected-host>:<port>/` and appends `server.base` when configured.

The functionality of [`Dev.assetPrefix`](#dev-assetprefix) is basically the same as the [output.publicPath](https://rspack.rs/config/output#outputpublicpath)
config in Rspack. With the following differences:

- `dev.assetPrefix` only takes effect during development.

- `dev.assetPrefix` automatically appends a trailing `/` by default.

- The value of `dev.assetPrefix` is written to the `process.env.ASSET_PREFIX` environment variable.

If `dev.assetPrefix` is set to true, the URL prefix will be `http://<host>:<port>/`:

```js
import { defineConfig } from '@lynx-js/rspeedy'
export default defineConfig({
  dev: {
    assetPrefix: true,
  },
})
```

If `dev.assetPrefix` is set to a string, the value will be used as a prefix and automatically appended to the static resource URL.

```js
import { defineConfig } from '@lynx-js/rspeedy'
export default defineConfig({
  dev: {
    assetPrefix: 'https://example.com/assets/',
  },
})
```

The port number that Rspeedy server listens on may change. For example, if the port is in use, Rspeedy will automatically increment the port number until it finds an available port.

To avoid `dev.assetPrefix` becoming invalid due to port changes, you can use one of the following methods:

- Enable `server.strictPort`.

- Use the `<port>` placeholder to refer to the current port number. Rspeedy will replace the placeholder with the actual port number it is listening on.

```js
import { defineConfig } from '@lynx-js/rspeedy'
export default defineConfig({
  dev: {
    assetPrefix: 'https://example.com:<port>/assets/',
  },
})
```

### `dev.hmr` \{#dev-hmr\}

- **Type:** `boolean`
- **Default:** `true`

Whether to enable Hot Module Replacement (HMR).

By default, Rspeedy uses HMR as the preferred method to update modules. If HMR is disabled or cannot be used in certain scenarios, it will automatically fallback to [`Dev.liveReload`](#dev-livereload).

To completely disable both HMR and live reload, set both `dev.hmr` and `dev.liveReload` to `false`. Then, no WebSocket requests will be made to the dev server on the page, and the page will not automatically refresh when file changes.

Disable HMR:

```js
import { defineConfig } from '@lynx-js/rspeedy'

export default defineConfig({
  dev: {
    hmr: false,
  },
})
```

Disable both HMR and live reload:

```js
import { defineConfig } from '@lynx-js/rspeedy'

export default defineConfig({
  dev: {
    hmr: false,
    liveReload: false,
  },
})
```

### `dev.liveReload` \{#dev-livereload\}

- **Type:** `boolean`
- **Default:** true

Live reload is used as a fallback when [`Dev.hmr`](#dev-hmr) is disabled or cannot be used in certain scenarios. When enabled, the page will automatically refresh when source files are changed.

To completely disable both HMR and live reload, set both `dev.hmr` and `dev.liveReload` to `false`. Then, no WebSocket requests will be made to the dev server on the page, and the page will not automatically refresh when file changes.

Whether to enable live reload functionality.

Disable live reload:

```js
import { defineConfig } from '@lynx-js/rspeedy'

export default defineConfig({
  dev: {
    liveReload: false,
  },
})
```

Disable both HMR and live reload:

```js
import { defineConfig } from '@lynx-js/rspeedy'

export default defineConfig({
  dev: {
    hmr: false,
    liveReload: false,
  },
})
```

### `dev.progressBar` \{#dev-progressbar\}

- **Type:** `boolean | { id?: string }`
- **Default:** `true`

Whether to display progress bar during compilation.

Disable the progress bar.

```js
import { defineConfig } from '@lynx-js/rspeedy'

export default defineConfig({
  dev: {
    progressBar: false,
  },
})
```

Modify the progress bar `id`

To modify the text displayed on the left side of the progress bar, set the `id` option:

```js
import { defineConfig } from '@lynx-js/rspeedy'

export default defineConfig({
  dev: {
    progressBar: {
      id: 'Some Text'
    },
  },
})
```

### `dev.watchFiles` \{#dev-watchfiles\}

- **Type:** `WatchFiles | WatchFiles[]`
- **Default:** `undefined`

Watch specified files and directories for changes. When a file change is detected, it can trigger a page reload or restart the dev server.

- Specify the files and directories watched for changes.

```js
import { defineConfig } from '@lynx-js/rspeedy'

export default defineConfig({
  dev: {
    watchFiles: {
      paths: ['src/**', 'public/**'],
    },
  },
})
```

- Use [chokidar](https://github.com/paulmillr/chokidar#api) options for watching.

```js
import { defineConfig } from '@lynx-js/rspeedy'

export default defineConfig({
  dev: {
    watchFiles: {
      paths: ['src/**', 'public/**'],
      options: { usePolling: false },
    },
  },
})
```

### `dev.writeToDisk` \{#dev-writetodisk\}

- **Type:** `boolean | ((filename: string) => boolean)`
- **Default:** `true`

Used to control whether the build artifacts of the development environment are written to the disk.

This is bypassed to [`webpack-dev-middleware`](https://github.com/webpack/webpack-dev-middleware?tab=readme-ov-file#writetodisk).

Setting `writeToDisk: true` won't change the behavior of the `webpack-dev-middleware`, and bundle files accessed through the browser will still be served from memory.

This option also accepts a `Function` value, which can be used to filter which files are written to disk.

The function follows the same premise as `Array#filter` in which a return value of `false` will not write the file, and a return value of `true` will write the file to disk.

```js
// lynx.config.ts
import { defineConfig } from '@lynx-js/rspeedy'
export default defineConfig({
  dev: {
    writeToDisk: (filePath) => /superman\.css$/.test(filePath),
  },
})
```
