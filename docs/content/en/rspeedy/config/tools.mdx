# tools

Escape hatches to the underlying tools: modify the Rspack configuration, the SWC options or the Rsbuild config directly when an option is not exposed by Rspeedy.

## Options

{/* @api ConfigOptions package="rspeedy" type="Config" path="tools" */}

### `tools.bundlerChain` \{#tools-bundlerchain\}

- **Type:** `ToolsBundlerChainConfig` (from [@rsbuild/core](https://rsbuild.rs/config/))
- **Default:** `undefined`

The [`Tools.bundlerChain`](#tools-bundlerchain) changes the options of [Rspack](https://rspack.rs) using [rspack-chain](https://github.com/rspack-contrib/rspack-chain).

```js
import { defineConfig } from '@lynx-js/rspeedy'

export default defineConfig({
  tools: {
    bundlerChain(chain) {
      chain.resolve.fullySpecified(true)
    },
  },
})
```

See [rspack-chain](https://github.com/rspack-contrib/rspack-chain) for details.

### `tools.cssExtract` \{#tools-cssextract\}

- **Type:** [`CssExtract`](#tools-cssextract)
- **Default:** `undefined`

The [`CssExtract`](#tools-cssextract) controls the options of [CssExtractRspackPlugin](https://rspack.rs/plugins/rspack/css-extract-rspack-plugin)

#### `tools.cssExtract.loaderOptions` \{#tools-cssextract-loaderoptions\}

- **Type:** [`CssExtractRspackLoaderOptions`](#tools-cssextract-loaderoptions)
- **Default:** `undefined`

`@lynx-js/css-extract-webpack-plugin#LoaderOptions`

##### `tools.cssExtract.loaderOptions.esModule` \{#tools-cssextract-loaderoptions-esmodule\}

- **Type:** `boolean`
- **Default:** `true`

The same as [https://github.com/webpack-contrib/mini-css-extract-plugin#esModule](https://github.com/webpack-contrib/mini-css-extract-plugin#esModule).
By default, `@lynx-js/css-extract-webpack-plugin` generates JS modules that use the ES modules syntax.
There are some cases in which using ES modules is beneficial,
like in the case of module concatenation and tree shaking.

You can enable a CommonJS syntax using:

```js
import {CssExtractRspackPlugin} from "@lynx-js/css-extract-webpack-plugin";
export default {
  plugins: [new CssExtractRspackPlugin()],
  module: {
    rules: [
      {
        test: /\.css$/i,
        use: [
          {
            loader: CssExtractRspackPlugin.loader,
            options: {
              esModule: false,
            },
          },
          "css-loader",
        ],
      },
    ],
  },
};
```

### `tools.cssLoader` \{#tools-cssloader\}

- **Type:** [`CssLoader`](#tools-cssloader)
- **Default:** Uses defaults derived from `output.cssModules` and `output.sourceMap`, with `importLoaders` set to `1` for CSS files and `2` for Sass/Less files.

The [`CssLoader`](#tools-cssloader) controls the options of [css-loader](https://github.com/webpack-contrib/css-loader).

The default option is as follow:

```js
const defaultOptions = {
  modules: {
    auto: true,
    namedExport: false,
    exportLocalsConvention: 'camelCase',
    localIdentName: output.cssModules.localIdentName,
  },
  sourceMap: output.sourceMap,
  // importLoaders is `1` when compiling css files, and is `2` when compiling sass/less files
  importLoaders: 1 || 2,
};
```

#### `tools.cssLoader.importLoaders` \{#tools-cssloader-importloaders\}

- **Type:** `0 | 1 | 2`
- **Default:** `1` when compiling CSS files and `2` when compiling Sass or Less files

The option `importLoaders` allows you to configure how many loaders before `css-loader` should be applied to `@imported` resources and CSS modules imports.

See [css-loader#import-loaders](https://github.com/webpack-contrib/css-loader?tab=readme-ov-file#importloaders) for details.

#### `tools.cssLoader.modules` \{#tools-cssloader-modules\}

- **Type:** `boolean | "local" | "global" | "pure" | "icss" | CssLoaderModules`
- **Default:** Enables CSS Modules with automatic `*.module.*` detection, camelCase exports, `namedExport: false`, and `localIdentName` inherited from `output.cssModules.localIdentName`.

The [`cssLoader.modules`](#cssloadermodules) option enables/disables the CSS Modules specification and setup basic behavior.

Using `false` value to increase performance because we avoid parsing CSS Modules features, it will be useful for developers who use vanilla css or use other technologies.

```js
import { defineConfig } from '@lynx-js/rspeedy'

export default defineConfig({
  tools: {
    cssLoader: {
      modules: false,
    },
  },
})
```

Using `() => true` value to enable CSS Modules for all files.

```js
import { defineConfig } from '@lynx-js/rspeedy'

export default defineConfig({
  tools: {
    cssLoader: {
      modules: () => true,
    },
  },
})
```

Using object value to enable CSS Modules based-on [`CssLoaderModules.auto`](#cssloadermodules-auto) option and setup more configurations about CSS Modules.

```js
import { defineConfig } from '@lynx-js/rspeedy'

export default defineConfig({
  tools: {
    cssLoader: {
      modules: {
        namedExport: true,
      },
    },
  },
})
```

### `tools.rsdoctor` \{#tools-rsdoctor\}

- **Type:** [`RsdoctorRspackPluginOptions`](#tools-rsdoctor)
- **Default:** `undefined`

The [`Tools.rsdoctor`](#tools-rsdoctor) controls the options of [Rsdoctor](https://rsdoctor.dev/).

Setting `RSDOCTOR=true` enables Rsdoctor. When it is enabled, Rspeedy merges additional plugin defaults during config normalization.

- Use the built-in Rsdoctor.

```js
import { defineConfig } from '@lynx-js/rspeedy'

export default defineConfig({
  tools: {
    rsdoctor: {
      disableClientServer: true,
    },
  },
})
```

See [Rsdoctor - Configuration](https://rsdoctor.dev/config/options/options) for details.

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| <a id="tools-rsdoctor-linter"></a>`linter` | `{ extends?: unknown[]; level?: "Ignore" \| "Warn" \| "Error"; rules?: Record<string, unknown> }` |  |  |

### `tools.rspack` \{#tools-rspack\}

- **Type:** `ToolsRspackConfig` (from [@rsbuild/core](https://rsbuild.rs/config/))
- **Default:** `undefined`

The [`Tools.rspack`](#tools-rspack) controls the options of [Rspack](https://rspack.rs/).

- Use object config

```js
import { defineConfig } from '@lynx-js/rspeedy'

export default defineConfig({
  tools: {
    rspack: {
      resolve: {
        fullySpecified: true,
      },
    },
  },
})
```

See [Rspack - Configuration](https://rspack.rs/config/index) for details.

- Use function with `env` utils

```js
import { defineConfig } from '@lynx-js/rspeedy'

export default defineConfig({
  tools: {
    rspack(config, { env }) {
      if (env === 'development') {
        config.devtool = 'cheap-source-map'
      }
      return config
    },
  },
})
```

See [Rsbuild - tools.rspack](https://rsbuild.rs/config/tools/rspack#env) for details.

- Use function with `mergeConfig` utils

```js
import { defineConfig } from '@lynx-js/rspeedy'

export default defineConfig({
  tools: {
    rspack(config, { mergeConfig }) {
      return mergeConfig(config, {
        resolve: {
          fullySpecified: true,
        },
      })
    },
  },
})
```

See [Rsbuild - tools.rspack](https://rsbuild.rs/config/tools/rspack#mergeconfig) for details.

- Use function with `appendPlugins` utils

```js
import { defineConfig } from '@lynx-js/rspeedy'

export default defineConfig({
  tools: {
    rspack(config, { appendPlugins, rspack }) {
      appendPlugins(new rspack.BannerPlugin({ banner: 'Hello, World!' }))
      return config
    },
  },
})
```

See [Rsbuild - tools.rspack](https://rsbuild.rs/config/tools/rspack#appendplugins) for details.
