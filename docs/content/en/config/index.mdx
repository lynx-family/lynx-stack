# Config overview

The options for building a Lynx app. The same options apply whichever way you build:

- **Rsbuild with [`pluginLynx`](/plugins/plugin-lynx)**: `rsbuild.config.ts` holds the Rsbuild options, and the Lynx-specific options are passed to `pluginLynx`.
- **Rspeedy**: `lynx.config.ts` holds all of them. Rspeedy applies `pluginLynx` for you and passes the Lynx-specific options on to it.

```ts title="rsbuild.config.ts"
import { defineConfig } from '@rsbuild/core'
import { pluginLynx } from '@lynx-js/rsbuild-plugin'
import { pluginReactLynx } from '@lynx-js/react-rsbuild-plugin'

export default defineConfig({
  source: {
    entry: { main: './src/index.tsx' },
  },
  environments: {
    lynx: {},
  },
  plugins: [
    pluginLynx({
      output: { filename: { bundle: '[name].[platform].bundle' } },
    }),
    pluginReactLynx(),
  ],
})
```

```ts title="lynx.config.ts"
import { defineConfig } from '@lynx-js/rspeedy'
import { pluginReactLynx } from '@lynx-js/react-rsbuild-plugin'

export default defineConfig({
  source: {
    entry: './src/index.tsx',
  },
  output: {
    filename: { bundle: '[name].[platform].bundle' },
  },
  plugins: [pluginReactLynx()],
})
```

Most options are standard [Rsbuild options](https://rsbuild.rs/config/) and link straight to the Rsbuild documentation. The options specific to Lynx have their own pages here, with how to set them in both setups. Rsbuild options that would break a Lynx bundle (`html`, `security`, `moduleFederation`, the polyfill settings) are not supported.

## Defaults that differ from Rsbuild \{#lynx-defaults\}

| Name | Lynx default | Rsbuild default |
| --- | --- | --- |
| [`environments`](https://rsbuild.rs/config/environments) | When this option is unset, Rspeedy passes `{ lynx: {} }` to Rsbuild. |  |
| [`mode`](https://rsbuild.rs/config/mode) | Depends on `process.env.NODE_ENV`: `'production'` when `NODE_ENV` is `'production'`, `'development'` when `NODE_ENV` is `'development'`, and `'none'` otherwise. When using Rspeedy's CLI, `rspeedy dev` and `rspeedy preview` default to `'development'`, while `rspeedy build` defaults to `'production'`. | Depends on `process.env.NODE_ENV`: - `'production'` if NODE_ENV is 'production' - `'development'` if NODE_ENV is 'development' - otherwise `'none'` |
| [`splitChunks`](https://rsbuild.rs/config/split-chunks) | Rspeedy defaults this to `false`; if configured, Rsbuild handles it with its top-level `splitChunks` option. See [Rsbuild - splitChunks](https://rsbuild.rs/config/split-chunks) for details. |  |
| [`source.entry`](https://rsbuild.rs/config/source/entry) | `'./src/index.js'` | `{ index: './src/index.js', }` |
| [`source.include`](https://rsbuild.rs/config/source/include) | When unset, Rsbuild compiles JavaScript files in the current directory and TypeScript or JSX files in all directories, while excluding JavaScript files under `node_modules`. | `[ { and: [rootPath, { not: /[\\/]node_modules[\\/]/ }], }, /\.(?:ts\|tsx\|jsx\|mts\|cts)$/, ];` |
| [`output.cleanDistPath`](https://rsbuild.rs/config/output/clean-dist-path) | Automatically enabled when `output.distPath.root` is a subdirectory of the project root; otherwise disabled. | `'auto'` |
| [`output.dataUriLimit`](https://rsbuild.rs/config/output/data-uri-limit) | `2048` | `{ svg: 4096, font: 4096, image: 4096, media: 4096, assets: 4096 }` |
| [`output.distPath`](https://rsbuild.rs/config/output/dist-path) | Uses Rsbuild's default distPath configuration with `root: 'dist'`. |  |
| [`output.filename`](https://rsbuild.rs/config/output/filename) | `{ bundle: '[name].[platform].bundle', template: '[name].[platform].bundle' }` |  |
| [`output.filenameHash`](https://rsbuild.rs/config/output/filename-hash) | In production web builds, Rsbuild defaults this option to `true`; development builds and non-web outputs omit hashes by default. | `true` |
| [`output.inlineScripts`](https://rsbuild.rs/config/output/inline-scripts) | Rspeedy defaults this to `true` and only switches it to `false` when the user explicitly enables the top-level `splitChunks` option. | `false` |
| [`output.legalComments`](https://rsbuild.rs/config/output/legal-comments) | `'none'` | `'linked'` |
| [`output.sourceMap`](https://rsbuild.rs/config/output/source-map) | When this option is unset in Lynx builds, JavaScript source maps use `'cheap-module-source-map'` in development and `'source-map'` in production; CSS source maps are also generated. All `.map` assets are removed before emit. | `const defaultSourceMap = { js: isDev ? 'cheap-module-source-map' : false, css: false, extract: false, };` |
| [`dev.progressBar`](https://rsbuild.rs/config/dev/progress-bar) | `true` | `false` |
| [`dev.writeToDisk`](https://rsbuild.rs/config/dev/write-to-disk) | `true` | `false` |
| [`server.cors`](https://rsbuild.rs/config/server/cors) | Uses Rsbuild's default CORS options. - Set to an object to enable CORS with the specified options. - Set to `true` to enable CORS with the default options (allows all origins, not recommended). - Set to `false` to disable CORS. See [Rsbuild - server.cors](https://rsbuild.rs/config/server/cors) for details. | `{ origin: defaultAllowedOrigins }` where `defaultAllowedOrigins` includes: - `localhost` - `127.0.0.1` - `[::1]` |
| [`server.host`](https://rsbuild.rs/config/server/host) | `"0.0.0.0"` | `'localhost'` |
| [`server.port`](https://rsbuild.rs/config/server/port) | Rsbuild defaults this option to `3000`. | `3000` |
| [`server.strictPort`](https://rsbuild.rs/config/server/strict-port) | `false By default, strict port mode is disabled. Set strictPort to true and Rspeedy will throw an exception when the port is occupied.` | `false` |
| [`resolve.extensions`](https://rsbuild.rs/config/resolve/extensions) | `['.ts', '.tsx', '.mjs', '.js', '.jsx', '.json', '.cjs']` For example, if importing './index', Rsbuild will try to resolve using the following order: - `./index.ts` - `./index.tsx` - `./index.mjs` - `./index.js` - `./index.jsx` - `./index.json` - `./index.cjs` | `['.ts', '.tsx', '.mjs', '.js', '.jsx', '.json']` |
| [`performance.chunkSplit`](https://rsbuild.rs/config/split-chunks) | For web builds, Rsbuild currently uses `{ strategy: 'split-by-experience' }` when this option is unset.  Use the top-level `Config.splitChunks` option instead. |  |
| [`tools.cssLoader`](https://rsbuild.rs/config/tools/css-loader) | Uses defaults derived from `output.cssModules` and `output.sourceMap`, with `importLoaders` set to `1` for CSS files and `2` for Sass/Less files. |  |
