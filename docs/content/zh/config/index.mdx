# 配置总览

构建 Lynx 应用的配置项。无论用哪种方式构建，配置项都是同一套：

- **Rsbuild + [`pluginLynx`](/zh/plugins/plugin-lynx)**：`rsbuild.config.ts` 中放 Rsbuild 配置，Lynx 特有配置传给 `pluginLynx`。
- **Rspeedy**：所有配置都放在 `lynx.config.ts` 中。Rspeedy 会自动应用 `pluginLynx`，并把 Lynx 特有配置转交给它。

```ts title="rsbuild.config.ts"
import { defineConfig } from '@rsbuild/core'
import { pluginLynx } from '@lynx-js/rsbuild-plugin'
import { pluginReactLynx } from '@lynx-js/react-rsbuild-plugin'

export default defineConfig({
  source: {
    entry: { main: './src/index.tsx' },
  },
  environments: {
    lynx: {},
  },
  plugins: [
    pluginLynx({
      output: { filename: { bundle: '[name].[platform].bundle' } },
    }),
    pluginReactLynx(),
  ],
})
```

```ts title="lynx.config.ts"
import { defineConfig } from '@lynx-js/rspeedy'
import { pluginReactLynx } from '@lynx-js/react-rsbuild-plugin'

export default defineConfig({
  source: {
    entry: './src/index.tsx',
  },
  output: {
    filename: { bundle: '[name].[platform].bundle' },
  },
  plugins: [pluginReactLynx()],
})
```

大多数配置项是标准的 [Rsbuild 配置](https://rsbuild.rs/zh/config/)，直接链接到 Rsbuild 文档。Lynx 特有的配置项在本站有单独的页面，并说明两种构建方式下的设置方法。会破坏 Lynx bundle 的 Rsbuild 配置（`html`、`security`、`moduleFederation` 以及 polyfill 相关设置）不受支持。

## 与 Rsbuild 默认值不同的配置 \{#lynx-defaults\}

| 名称 | Lynx 默认值 | Rsbuild 默认值 |
| --- | --- | --- |
| [`environments`](https://rsbuild.rs/zh/config/environments) | 未设置该选项时，Rspeedy 会向 Rsbuild 传入 `{ lynx: {} }`。 |  |
| [`mode`](https://rsbuild.rs/zh/config/mode) | 取决于 `process.env.NODE_ENV`：当 `NODE_ENV` 为 `'production'` 时为 `'production'`，为 `'development'` 时为 `'development'`，其他情况下为 `'none'`。使用 Rspeedy CLI 时，`rspeedy dev` 和 `rspeedy preview` 默认为 `'development'`，而 `rspeedy build` 默认为 `'production'`。 | Depends on `process.env.NODE_ENV`: - `'production'` if NODE_ENV is 'production' - `'development'` if NODE_ENV is 'development' - otherwise `'none'` |
| [`splitChunks`](https://rsbuild.rs/zh/config/split-chunks) | Rspeedy 默认将其设置为 `false`；如果进行了配置，则由 Rsbuild 的顶层 `splitChunks` 选项处理。 详见 [Rsbuild - splitChunks](https://rsbuild.rs/config/split-chunks)。 |  |
| [`source.entry`](https://rsbuild.rs/zh/config/source/entry) | `'./src/index.js'` | `{ index: './src/index.js', }` |
| [`source.include`](https://rsbuild.rs/zh/config/source/include) | 未设置时，Rsbuild 会编译当前目录下的 JavaScript 文件以及所有目录下的 TypeScript 或 JSX 文件，同时排除 `node_modules` 下的 JavaScript 文件。 | `[ { and: [rootPath, { not: /[\\/]node_modules[\\/]/ }], }, /\.(?:ts\|tsx\|jsx\|mts\|cts)$/, ];` |
| [`output.cleanDistPath`](https://rsbuild.rs/zh/config/output/clean-dist-path) | 当 `output.distPath.root` 为项目根目录的子目录时自动启用，否则禁用。 | `'auto'` |
| [`output.dataUriLimit`](https://rsbuild.rs/zh/config/output/data-uri-limit) | `2048` | `{ svg: 4096, font: 4096, image: 4096, media: 4096, assets: 4096 }` |
| [`output.distPath`](https://rsbuild.rs/zh/config/output/dist-path) | 使用 Rsbuild 默认的 distPath 配置，并设置 `root: 'dist'`。 |  |
| [`output.filename`](https://rsbuild.rs/zh/config/output/filename) | `{ bundle: '[name].[platform].bundle', template: '[name].[platform].bundle' }` |  |
| [`output.filenameHash`](https://rsbuild.rs/zh/config/output/filename-hash) | 在生产环境 web 构建中，Rsbuild 默认将该选项设置为 `true`；开发环境构建和非 web 产物默认不添加 hash。 | `true` |
| [`output.inlineScripts`](https://rsbuild.rs/zh/config/output/inline-scripts) | Rspeedy 默认将其设置为 `true`，仅当用户显式启用顶层的 `splitChunks` 选项时才会切换为 `false`。 | `false` |
| [`output.legalComments`](https://rsbuild.rs/zh/config/output/legal-comments) | `'none'` | `'linked'` |
| [`output.sourceMap`](https://rsbuild.rs/zh/config/output/source-map) | 在 Lynx 构建中未设置该选项时，JavaScript source map 在开发环境使用 `'cheap-module-source-map'`，在生产环境使用 `'source-map'`；同时也会生成 CSS source map。所有 `.map` 资源都会在输出前被移除。 | `const defaultSourceMap = { js: isDev ? 'cheap-module-source-map' : false, css: false, extract: false, };` |
| [`dev.progressBar`](https://rsbuild.rs/zh/config/dev/progress-bar) | `true` | `false` |
| [`dev.writeToDisk`](https://rsbuild.rs/zh/config/dev/write-to-disk) | `true` | `false` |
| [`server.cors`](https://rsbuild.rs/zh/config/server/cors) | 使用 Rsbuild 默认的 CORS 选项。 - 设置为对象时，使用指定的选项启用 CORS。 - 设置为 `true` 时，使用默认选项启用 CORS（允许所有来源，不推荐）。 - 设置为 `false` 时，禁用 CORS。 详见 [Rsbuild - server.cors](https://rsbuild.rs/config/server/cors)。 | `{ origin: defaultAllowedOrigins }` where `defaultAllowedOrigins` includes: - `localhost` - `127.0.0.1` - `[::1]` |
| [`server.host`](https://rsbuild.rs/zh/config/server/host) | `"0.0.0.0"` | `'localhost'` |
| [`server.port`](https://rsbuild.rs/zh/config/server/port) | Rsbuild 默认将该选项设置为 `3000`。 | `3000` |
| [`server.strictPort`](https://rsbuild.rs/zh/config/server/strict-port) | `false By default, strict port mode is disabled. Set strictPort to true and Rspeedy will throw an exception when the port is occupied.` | `false` |
| [`resolve.extensions`](https://rsbuild.rs/zh/config/resolve/extensions) | `['.ts', '.tsx', '.mjs', '.js', '.jsx', '.json', '.cjs']` 例如，导入 './index' 时，Rsbuild 会按以下顺序尝试解析： - `./index.ts` - `./index.tsx` - `./index.mjs` - `./index.js` - `./index.jsx` - `./index.json` - `./index.cjs` | `['.ts', '.tsx', '.mjs', '.js', '.jsx', '.json']` |
| [`performance.chunkSplit`](https://rsbuild.rs/zh/config/split-chunks) | 对于 web 构建，未设置该选项时 Rsbuild 当前使用 `{ strategy: 'split-by-experience' }`。  请使用顶层的 `Config.splitChunks` 选项代替。 |  |
| [`tools.cssLoader`](https://rsbuild.rs/zh/config/tools/css-loader) | 使用基于 `output.cssModules` 和 `output.sourceMap` 推导出的默认值，其中 CSS 文件的 `importLoaders` 设置为 `1`，Sass/Less 文件设置为 `2`。 |  |
