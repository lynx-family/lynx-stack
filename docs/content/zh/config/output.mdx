# output

控制构建产物写入磁盘的选项：输出位置、文件命名，以及是否压缩、是否生成 source map。

其中大多数是标准的 Rsbuild 配置：在 `rsbuild.config.ts` 的 `output` 下设置，使用 Rspeedy 构建时则在 `lynx.config.ts` 中设置，详细说明请查看 Rsbuild 文档。Lynx 特有的配置项在下文完整说明，并注明使用 Rsbuild 构建时应在哪里设置。

```ts title="rsbuild.config.ts"
import { defineConfig } from '@rsbuild/core'
import { pluginLynx } from '@lynx-js/rsbuild-plugin'

export default defineConfig({
  output: {
    sourceMap: true,
  },
  plugins: [
    pluginLynx({
      output: {
        filename: { bundle: '[name].[platform].bundle' },
      },
    }),
  ],
})
```

```ts title="lynx.config.ts"
import { defineConfig } from '@lynx-js/rspeedy'

export default defineConfig({
  output: {
    filename: { bundle: '[name].[platform].bundle' },
    sourceMap: true,
  },
})
```

## Lynx 特有配置 \{#lynx-options\}

### `output.filename.bundle` \{#output-filename-bundle\}

- **类型:** `BundleFilename`
- **默认值:** `'[name].[platform].bundle'`

bundle 文件的名称。

支持以下占位符：

- `[name]`：入口名称。
- `[contenthash]`：bundle 的 contenthash。
- `[platform]`：bundle 的 environment 名称。

- 在 bundle 文件名中使用 content hash：

```js
import { defineConfig } from '@lynx-js/rspeedy'

export default defineConfig({
  output: {
    filename: {
      bundle: '[name].[contenthash].bundle',
    },
  },
})
```

- 在 bundle 文件名中使用指定长度的 content hash：

```js
import { defineConfig } from '@lynx-js/rspeedy'

export default defineConfig({
  output: {
    filename: {
      bundle: '[name].[contenthash:8].bundle',
    },
  },
})
```

- 使用函数分别控制主 bundle 和 lazy bundle
  （例如将 lazy bundle 输出到另一个目录，并附加 git
  commit hash）：

```js
import { execSync } from 'node:child_process'

import { defineConfig } from '@lynx-js/rspeedy'

const gitHash = execSync('git rev-parse --short HEAD').toString().trim()

export default defineConfig({
  output: {
    filename: {
      bundle: ({ lazyBundle, platform }) =>
        lazyBundle
          ? `my-lazy-bundles/[name].[fullhash]-${gitHash}.bundle`
          : `[name].${platform}.bundle`,
    },
  },
})
```

使用 Rsbuild 构建时，将此选项传给 [`pluginLynx`](/zh/plugins/plugin-lynx#output-filename-bundle)。

### `output.minify.backgroundOptions` \{#output-minify-backgroundoptions\}

- **类型:** `SwcJsMinimizerRspackPluginOptions` (来自 [@rspack/core](https://rspack.rs/config/))
- **默认值:** `undefined`

[`Minify.backgroundOptions`](#output-minify) 用于为后台线程 bundle 覆盖
[`Minify.jsOptions`](#output-minify)。

该选项会被深度合并到 [`Minify.jsOptions`](#output-minify) 中。
它主要与 ReactLynx 的双线程产物配合使用，使
主线程和后台线程的 bundle 可以使用不同的压缩规则。

使用 Rsbuild 构建时，将此选项传给 [`pluginLynx`](/zh/plugins/plugin-lynx#output-minify-backgroundoptions)。

### `output.minify.mainThreadOptions` \{#output-minify-mainthreadoptions\}

- **类型:** `SwcJsMinimizerRspackPluginOptions` (来自 [@rspack/core](https://rspack.rs/config/))
- **默认值:** `undefined`

[`Minify.mainThreadOptions`](#output-minify) 用于为主线程 bundle 覆盖
[`Minify.jsOptions`](#output-minify)。

该选项会被深度合并到 [`Minify.jsOptions`](#output-minify) 中。
它主要与 ReactLynx 的双线程产物配合使用，使
主线程和后台线程的 bundle 可以使用不同的压缩规则。

```ts
import { defineConfig } from '@lynx-js/rspeedy'

export default defineConfig({
  output: {
    minify: {
      jsOptions: {
        minimizerOptions: {
          compress: {
            pure_funcs: ['console.log'],
          },
        },
      },
      mainThreadOptions: {
        minimizerOptions: {
          compress: {
            pure_funcs: ['NativeModules.call', 'lynx.getJSModule'],
          },
        },
      },
    },
  },
})
```

使用 Rsbuild 构建时，将此选项传给 [`pluginLynx`](/zh/plugins/plugin-lynx#output-minify-mainthreadoptions)。
