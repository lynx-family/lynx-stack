Vanilla DSL 插件。它从直接调用 Element PAPI 的纯 JavaScript 构建 Lynx bundle，不依赖 UI 框架。

## 安装

import { PackageManagerTabs } from '@rspress/core/theme';

<PackageManagerTabs command="add @lynx-js/vanilla-rsbuild-plugin -D" />

## 用法

```ts title="lynx.config.ts"
import { defineConfig } from '@lynx-js/rspeedy'
import { pluginVanillaLynx } from '@lynx-js/vanilla-rsbuild-plugin'

export default defineConfig({
  plugins: [pluginVanillaLynx()],
})
```

## 选项

{/* @api ApiOptions package="vanilla-rsbuild-plugin" type="PluginVanillaLynxOptions" */}

### `bundleFilename` \{#bundlefilename\}

- **类型:** [`VanillaBundleFilename`](#vanillabundlefilename)

覆盖最终的 `.bundle` 文件名。

在 Rspeedy 下省略时，使用 `output.filename.bundle`。
在 Rspeedy 之外，默认值为 `[name].[platform].bundle`。

### `entries` \{#entries\}

- **类型:** `Record<string, `[`VanillaLynxEntry`](#vanillalynxentry)`>` (来自 typescript)

显式声明的双线程入口。

省略时，每个 Rsbuild `source.entry` 都会被视为主线程
入口，并按约定发现同级目录下可选的 `background.ts` 和
`style.css` 文件。

## 函数 \{#\}

### `pluginVanillaLynx()` \{#pluginvanillalynx\}

```ts
pluginVanillaLynx(options: PluginVanillaLynxOptions): RsbuildPlugin
```

为 Rsbuild 或 Rspeedy 创建 Vanilla Lynx DSL 集成。

逻辑入口可以显式声明其主线程与后台线程
源文件。作为简写，Rsbuild 入口会被视为主线程
源文件，并按约定发现同级可选的 `background.ts` 和 `style.css`
文件。

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `options` | [`PluginVanillaLynxOptions`](#pluginvanillalynxoptions) |  |

**返回值:** `RsbuildPlugin`

### `TemplateHooks` \{#templatehooks\}

为便于其他插件修改 template，该插件会执行
[tapable](https://github.com/webpack/tapable) 钩子。

```js
class MyPlugin {
  apply(compiler) {
    compiler.hooks.compilation.tap("MyPlugin", (compilation) => {
      console.log("The compiler is starting a new compilation...");

      LynxTemplatePlugin.getLynxTemplatePluginHooks(compilation).beforeEmit.tapAsync(
        "MyPlugin", // <-- Set a meaningful name here for stacktraces
        (data, cb) => {
          // Manipulate the content
          modifyTemplate(data.template)
          // Tell webpack to move on
          cb(null, data);
        },
      );
    });
  }
}
```

| 成员 | 类型 | 说明 |
| --- | --- | --- |
| <a id="templatehooks-afteremit"></a>`afterEmit` <span className="api-badge api-badge-alpha">Alpha</span> | `AsyncSeriesWaterfallHook<{ outputName: string }>` (来自 @rspack/lite-tapable) | 在 template 输出后调用。 |
| <a id="templatehooks-asyncchunkname"></a>`asyncChunkName` <span className="api-badge api-badge-alpha">Alpha</span> | `SyncWaterfallHook<string>` (来自 @rspack/lite-tapable) | 获取异步 chunk 的真实名称。`asyncChunkName` 相同的文件会被放入同一个 template。 |
| <a id="templatehooks-beforeemit"></a>`beforeEmit` <span className="api-badge api-badge-alpha">Alpha</span> | `AsyncSeriesWaterfallHook<{ chunkGroups: ChunkGroup[]; cssChunks: Asset[]; cssDiagnostics?: string; debugInfo: string; finalEncodeOptions: EncodeOptions; mainThreadAssets: Asset[]; outputName: string; template: Buffer }>` (来自 @rspack/lite-tapable) | 在 template 输出前调用，可用于修改 template。 |
| <a id="templatehooks-beforeencode"></a>`beforeEncode` <span className="api-badge api-badge-alpha">Alpha</span> | `AsyncSeriesWaterfallHook<{ chunkGroups: ChunkGroup[]; encodeData: EncodeRawData; filenameTemplate: string; intermediate: string; intermediateAssets: string[] }>` (来自 @rspack/lite-tapable) | 在编码流程开始前调用，可用于修改编码选项。 |
| <a id="templatehooks-encode"></a>`encode` <span className="api-badge api-badge-alpha">Alpha</span> | `AsyncSeriesBailHook<{ encodeOptions: EncodeOptions; intermediate?: string }, { buffer: Buffer; cssDiagnostics?: string; debugInfo: string }>` (来自 @rspack/lite-tapable) | 执行编码流程。 |
