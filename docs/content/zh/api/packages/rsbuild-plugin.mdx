# @lynx-js/rsbuild-plugin

以 Rsbuild 插件形式提供的 Lynx 构建引擎。借助它可以直接使用 Rsbuild CLI 构建 Lynx 应用，无需 Rspeedy CLI。

[`pluginReactLynx`](/zh/api/packages/react-rsbuild-plugin) 等 DSL 插件会在构建引擎缺失时自动注册它，因此只有在需要传入下列选项时才需要自行添加 `pluginLynx`。Rspeedy 同样会自动注册它，并转发 `lynx.config.ts` 中的 `output.filename` 和 `performance.profile`。

## 安装

import { PackageManagerTabs } from '@rspress/core/theme';

<PackageManagerTabs command="add @lynx-js/rsbuild-plugin -D" />

## 用法

在 `rsbuild.config.ts` 中将该插件与 DSL 插件一同注册。environment 名称（下例中为 `lynx`）会作为 bundle 文件名中的 `[platform]` 占位符，因此该配置的默认产物为 `dist/main.lynx.bundle`。

```ts title="rsbuild.config.ts"
import { defineConfig } from '@rsbuild/core'
import { pluginReactLynx } from '@lynx-js/react-rsbuild-plugin'
import { pluginLynx } from '@lynx-js/rsbuild-plugin'

export default defineConfig({
  source: {
    entry: { main: './src/index.tsx' },
  },
  environments: {
    lynx: {},
  },
  plugins: [
    pluginLynx({
      performance: { profile: false },
    }),
    pluginReactLynx(),
  ],
})
```

然后使用 Rsbuild CLI：

```bash
rsbuild dev
rsbuild build
```

## 从 Rspeedy 迁移

将 `rspeedy dev` / `rspeedy build` 替换为 `rsbuild dev` / `rsbuild build`，将 `lynx.config.ts` 重命名为 `rsbuild.config.ts`，并从 `@rsbuild/core` 导入 `defineConfig`。原先由 Rspeedy 转发给构建引擎的两个选项，现在直接传给 `pluginLynx`：

| `lynx.config.ts` (Rspeedy) | `pluginLynx()` (Rsbuild) |
| --- | --- |
| `output.filename`（字符串形式） | `output.filename.bundle` |
| `output.filename.bundle` | `output.filename.bundle` |
| `output.filename.template`（已废弃） | `output.filename.bundle` |
| `performance.profile` | `performance.profile` |

`output`、`source`、`dev` 和 `server` 中的其余选项保持 Rsbuild 的结构，仍放在 `rsbuild.config.ts` 中。构建引擎会在 Rsbuild 默认值之上应用 Lynx 专属的默认值（bundle target、chunk 加载、CSS 提取、source map），并且仅在其他插件尚未设置时才覆盖对应配置。

## 选项

{/* @api ApiOptions package="rsbuild-plugin" type="LynxPluginOptions" */}

<a id="lynxpluginoptions"></a>

### `output` \{#output\}

- **类型：** [`LynxOutput`](#output)

构建产物。

#### `output.filename` \{#output-filename\}

- **类型：** [`LynxFilename`](#output-filename)

输出文件的名称。

##### `output.filename.bundle` \{#output-filename-bundle\}

- **类型：** [`BundleFilename`](#bundlefilename)
- **默认值：** `'[name].[platform].bundle'`

bundle 文件的名称。

支持以下占位符：

- `[name]`：入口名称。
- `[platform]`：Rsbuild environment 的名称。

#### `output.minify` \{#output-minify\}

- **类型：** [`LynxMinify`](#output-minify)

按线程配置的压缩器选项。

| 名称 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| <a id="output-minify-backgroundoptions"></a>`backgroundOptions` | `SwcJsMinimizerRspackPluginOptions` |  | 后台线程的压缩器选项。 |
| <a id="output-minify-mainthreadoptions"></a>`mainThreadOptions` | `SwcJsMinimizerRspackPluginOptions` |  | 主线程的压缩器选项。 |

### `performance` \{#performance\}

- **类型：** [`LynxPerformance`](#performance)

性能选项。

#### `performance.profile` \{#performance-profile\}

- **类型：** `boolean`

是否在 Lynx 运行时集成（如
ReactLynx）中采集耗时信息。

启用后，框架会使用 `console.profile`
记录运行时信息。

## 函数 \{#\}

### `isPluginLynxRegistered()` \{#ispluginlynxregistered\}

```ts
isPluginLynxRegistered(host: { isPluginExists: any }, environments: string[]): boolean
```

Lynx 构建引擎是否已注册。

该引擎是全局的。不传 environment 调用 `isPluginExists` 时只会
报告全局插件，因此无法检测到调用方（例如 `rslib`）
注册在某个 environment 上的引擎。

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `host` | `{ isPluginExists: any }` | The Rsbuild instance or plugin API to look it up on. |
| `environments` | `string[]` | The names of the configured environments. |

**返回值：** `boolean`

### `pluginLynx()` \{#pluginlynx\}

pluginLynx(options: LynxPluginOptions): RsbuildPlugin[]

| 参数 | 类型 | 说明 |

| `options` | [`LynxPluginOptions`](#lynxpluginoptions) |  |

const PLUGIN_LYNX_NAME: "lynx:rsbuild"

### `LynxConfig` <span className="api-badge api-badge-beta">Beta</span> \{#lynxconfig\}

`pluginLynx` 暴露给其他插件的 Lynx 配置。

该数据与 [`LynxPluginOptions`](#lynxpluginoptions) 保持一致，因此插件读取
`config.output.filename` 的方式与从
`api.getRsbuildConfig()` 读取 `output.filename` 相同。依赖于当前构建入口的值
由方法推导得出，这些方法随数据一起传递，从而确保
始终由构建该配置的插件来解析这些值。

```js
const lynx = getLynxConfig(api)
const filename = lynx.resolveBundleFilename({
  entryName: 'main',
  platform: environment.name,
})
```

| 成员 | 类型 | 说明 |
| --- | --- | --- |
| <a id="lynxconfig-output"></a>`output` <span className="api-badge api-badge-beta">Beta</span> | [`LynxOutput`](#output) | 构建产物。 |
| <a id="lynxconfig-performance"></a>`performance` <span className="api-badge api-badge-beta">Beta</span> | [`LynxPerformance`](#performance) | 性能选项。 |
| <a id="lynxconfig-resolvebundlefilename"></a>`resolveBundleFilename` | `resolveBundleFilename(context: { entryName: string; platform: string }): string` | 解析入口的 bundle 文件名。 |
| <a id="lynxconfig-resolveintermediatedir"></a>`resolveIntermediateDir` | `resolveIntermediateDir(context?: { entryName?: string }): string` | 解析中间产物所在的目录。 |
| <a id="lynxconfig-resolvelazybundlefilename"></a>`resolveLazyBundleFilename` | `resolveLazyBundleFilename(context: { platform: string }): string \| undefined` | 解析 lazy bundle 文件的名称。 |

### `BundleFilename` \{#bundlefilename\}

type BundleFilename = string | ((context: BundleFilenameContext) => string)

bundle 文件的名称。
